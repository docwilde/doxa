# Plan status

Audited against the native Rust tree on 2026-10-09. A Python-era plan's
"shipped" label describes that historical release; it is not evidence that
every proposed extension exists in Rust.

| Work | Current status |
| --- | --- |
| [Session Docker isolation](session-isolation-docker.md) | Native, open-egress and offline Linux profiles ship with private clones and cgroup checks. The gateway checks exact SNI/DNS and bounds the ClientHello. Ext4 four-bind `EDQUOT` and a 32-case helper/client/install fixture passed in disposable guests. Inactive root-owned systemd templates and a read-only install preflight require an independently reviewed helper digest; no installed-host activation has run. Production hook frames require per-message kernel writer metadata. The guarded gateway checks kernel writer identity for CONNECT, ClientHello and each worker-to-upstream relay chunk, then rechecks pinned connector scope before forwarding. These sequential observations cannot exclude movement between send, inspection and write. Exact Engine/container and provider origin remain unproved; no production profile starts the gateway, so hardened admission stays closed. See the [operator guide](../session-isolation.md). |
| [Independent fleet supervision](fleet-supervision.md) | Typed host gates, selectable independent review and frozen scopes exist. Dependency release binds a work checkpoint, its successor handoff turn, receiver read-back, sender agreement, and the latest handoff to explicit human review. Opt-in automatic test receipts remain separate from release. A read-only debrief reports bounded host evidence after a run. Live full-fleet validation and a consented real-message corpus remain open. See the [operator guide](../fleet-supervision.md). |
| [Claude permissions](../manual.md) | Switching to `auto` during a turn retries ordinary approvals waiting under the previous mode and removes the second DOXA approval for provider-approved canonical tools. Questions, explicit asks and the independent spawn gate remain interactive; new provider approval cards show Claude's reason. Native provider fixtures cover these paths. A control-only check against Claude Code 2.1.296 accepted the mode switch without a model turn; authenticated Bash classification remains unverified. |
| [Remote hub and Android](remote-hub.md) | Native/browser control, an encrypted Chrome client, browser Web Push and opt-in mixed-pane restore exist. Android FCM source tests and offline emulator builds pass; the normal connection and synthetic recovery screens were captured offline. Beta.28 saves body-free markers before writes, fences uncertain outcomes, and binds approvals to exact reviewed inputs and random session incarnations. Provisioned device/FCM and two-host tailnet QA remain open. |
| [Model registry](model-registry.md) | Exact-model sourced facts feed the picker and conservative budget bounds. Beta.23 adds read-only `doxa model-facts` with per-field source dates and operator-selected review candidates. The `gpt-6-astra` supervisor and judge selectors have sourced facts and regression coverage; live account availability, latency, billed tier and provider charge remain unknown. Provider catalogs still control availability. |
| [Code graph](code-graph.md) | Rust and Python syntax queries and reviewed LORE snapshots recheck listed sources before complete claims. Git commands and source reads have deadlines; a blocked reader can persist until process exit. The [disabled one-socket probe](codegraph-semantic-verification.md) joins exact-ID inspect, attach and one bounded LSP exchange with repeated, bounded observations of all local worktree entries, including ignored files. Sequential reads are non-atomic, can miss restored edits, and do not prove container-mounted bytes; a same-UID fake daemon can pass. Engine identity, full LSP session, cleanup and immutable source snapshots remain unproved; semantic `binding: unknown` and production admission stay closed. An automatic index remains open. |
| [DOXA plugin API](plugin-api.md) | Owner-allowlisted text commands and status files are data only. The approved zero-grant CLI worker passed a seven-case delegated guest proof; a review-only receipt binds its exact test artifact. The Linux runner rejects writable delegated cgroup components and rechecks opened worker and Bubblewrap metadata immediately before exec, but a same-user edit in the final check-to-exec interval remains possible. Read-only `doxa native-plugin host-check` inventories host identities without issuing authority. The review-only nine-case installed-host run has not occurred. The TUI has an owner-bound, cancellable run request; worker dispatch requires installed-host authority that production does not issue. Installed-host acceptance and production TUI admission remain closed; grants, hooks and provider extensions remain open. |
| [Mermaid transcript diagrams](mermaid.md) | Opt-in local previews, sandbox doctor and beta.16 Settings preflight exist. A private session PNG cache binds source, width, and renderer package identity. A pinned real CLI suite passed fixed diagrams in Linux sandbox; real terminal graphics QA and an optional installer decision remain open. |
| [Collection triage](collection-triage.md) | Suggested names, settled opt-in group sorting and verified local LORE pending rank exist. Beta.16 added verified project heading hues and hidden-tab urgency; beta.17 added pane-row navigation, manual collection hues and label rename. Beta.18 adds `/collection project-label` for freshly verified canonical roots; unresolved or mixed roots stay read-only. |

An opt-in source-only Claude lifecycle harness is available; an authenticated macOS pass and protected Codex success remain unverified. |
